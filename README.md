# Lead Response Engine — public demo

A public, $0, production-grade demo proving a speed-to-lead automation
behaves — to a med-spa owner deciding whether to buy, and to a hiring
engineer deciding whether the person who built it is serious — that says
exactly what each thing on the page is.

## The honesty architecture, in one paragraph

Every label on every page — "Simulator", "Recording", what's real, what's
stubbed, what's simulated, whether anything was ever sent — is composed
from a committed `run.json` file (`packages/schema/src/labels.ts`), never
typed into a template. Softening a claim requires lying in a file that CI
validates (`pnpm check:runs`, `pnpm check:drift`) and that a reviewer can
open directly. **A real n8n recording exists (milestone M1).** A local n8n
instance genuinely executed `content/workflow.json`, with GoHighLevel,
Slack and Google Sheets answered by a local `stubhouse` — never a live
account — see `capture/README.md` for exactly how, and
`content/runs/rec-medspa-happy/` / `rec-medspa-slack-401/` for the two
committed recordings (`mode: "recording"`, `execution.json` + `attest.json`
alongside each `run.json`). Five simulator runs also still exist
(`mode: "simulator"`): a deterministic TypeScript executor
(`packages/engine`) walks the same 14-node topology with modeled per-node
timings — `/demo`'s Simulator tab shows one, next to the Recording tab.

## Quickstart

Requires Node ≥22.12 and pnpm ≥9 (pinned: `pnpm@9.15.4`, see
`packageManager` in `package.json`).

```bash
pnpm install
pnpm verify          # typecheck, tests, drift/binding/secret checks, build, e2e — everything CI runs
pnpm --filter @lrd/site dev     # site at http://localhost:4321
pnpm --filter @lrd/worker dev   # worker at http://localhost:8787 (GET /api/health only)
```

Individual gates:

```bash
pnpm typecheck        # every workspace package + root scripts/tests
pnpm test             # vitest: unit tests + committed golden traces
pnpm gen:runs         # regenerate content/runs/ from packages/engine
pnpm check:runs       # regeneration matches what's committed, byte-for-byte
pnpm check:drift      # every committed run's node list still matches content/workflow.json
pnpm check:bindings   # the Worker's binding list is DB + TURNSTILE_SECRET, nothing else
pnpm check:secrets    # no secret-shaped strings anywhere in the tracked tree
pnpm build            # astro build -> site/dist
pnpm e2e              # Playwright: 320px overflow, zero-JS, JS-disabled rendering
```

## Repo structure (Spec section 5)

```
packages/schema/   Zod schemas + types every other package/site consumes
packages/engine/   pure TS topology executor — no I/O, no DOM, deterministic
site/              Astro static site (imports engine + schema, reads content/runs/)
worker/            Hono Worker — HTTP surface, no topology logic (M0: /api/health only)
capture/           the M1 recording rig — stubhouse + capture.mjs, runs for real
content/           workflow.json (the base n8n export) + the committed runs
scripts/           generate-runs, drift-check, check-bindings, check-secrets, e2e
tests/e2e/          Playwright suite
docs/              PROGRESS, DEVIATIONS, LIMITATIONS, M0-REPORT, M1-REPORT, screenshots
```

## Deploying (documented, not run this session)

No remote exists for this repo yet, and per this session's own scope
nothing gets pushed or deployed from here. When it does, from the repo
root after `pnpm build`:

```bash
npx wrangler pages deploy site/dist --project-name <name>
```

`<name>` is unresolved on purpose: Spec section 18 defers the product name
to the identity brief (blocking M3), and until then the dispatcher decision
is a free `*.pages.dev` subdomain, not a purchased domain. The Worker (M2+)
deploys separately: `cd worker && npx wrangler deploy`.
